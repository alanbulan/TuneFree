# 推荐数据库迁移

SQL 文件以 `YYYY-MM-DD_NNN_用途.sql` 命名。现有脚本的 `2026-11-15` 是从 Rust 提取到 SQL 文件的整理日期，不代表历史迁移首次发布的日期。

| 执行顺序 | 文件 | 版本与行为 |
| --- | --- | --- |
| 基础结构 | `2026-11-15_001_schema.sql` | 每次启动幂等创建基础表；不新增或改写历史版本 1 |
| 2 | `2026-11-15_002_reset_derived_data.sql` | 保留原版本 2，清理曲库画像和共现派生数据 |
| 3 | `2026-11-15_003_event_weights.sql` | 保留原版本 3，修正事件权重并清理共现数据 |
| 4 | `2026-11-15_004_recommendation_clicks.sql` | 保留原版本 4，区分推荐点击与相似歌曲点击 |
| 5 | `2026-11-15_005_llm_timeout.sql` | 保留原版本 5，一次性升级旧 8 秒默认超时 |
| 6 | `2026-11-16_006_refresh_state.sql` | 保存明确偏好变化与云端尝试时间，重启保留冷却 |

`migration.rs` 通过 `include_str!` 编译嵌入 SQL，按上表显式执行，不按运行时目录扫描或文件名排序。默认配置插入、旧表按需新增凭据列、参数绑定和事务编排保留在 Rust。`migration_timeout.rs` 提供版本 5 的参数与事务。

版本 2–6 使用 `recommendation_schema_migrations` 的数字记录；已执行的版本跳过。每个版本的数据修改、待重建标记和版本记录在同一事务提交，失败整体回滚。画像和共现重建仍由后台执行，启动只记录待办。

新增迁移时使用实际开发日期、递增且未使用的数字版本，并在 Rust 的执行列表末尾显式调用。不要修改旧脚本来修正已发布数据；另加迁移。SQL 不自行提交事务，也不访问应用凭据或真实用户数据库。回归测试放在相邻 `__tests__/`，覆盖老库保留、幂等和失败恢复。
