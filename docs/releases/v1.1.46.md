# TuneFree v1.1.46

## 性能优化

- 音乐伙伴空闲更新为 30Hz，指针交互与形变过渡保持 60Hz，动画按实际经过时间推进。
- 频谱保留 220 根柱子，绘制上限为 30Hz，预先计算频率映射；暂停衰减按时间计算，窗口隐藏时停止调度。
- 桌面歌词逐行 / 逐字状态更新分别限制为 10 / 30Hz，seek、新播放进度与暂停立即同步。
- 移除音乐库根节点无用途的聚合状态订阅，子页继续读取需要的状态。

固定场景对照中，5 秒播放的脚本耗时 145.5 → 83.9ms，逐行歌词 68.8 → 17.6ms；隔离 About 页的 20 秒原生进程合计 CPU 14.40% → 11.05%。这些短样本说明对应场景的收益，不外推到所有页面、真实平台网络、整机内存或续航。5000 首歌单的 30 轮操作最多渲染 24 行，DOM 与监听没有随导航累积，页面异常为 0。

## 代码整理

- 推荐数据库基础结构和版本 2–5 的 SQL 移入 `recommendation/migrations/2026-11-15_NNN_用途.sql`，标明整理日期与顺序。保留原数字版本、事务回滚、旧配置与后台重建行为，已升级的数据库不会重新迁移。
- 迁移测试按事件语义和事务边界拆到相邻 `__tests__/`，补充失败回滚、恢复重试和重复启动回归。
- 统一 `BloubCompanion` / `useCompanionPosition` 命名，保留原位置存储键；删除闲置工具、重复图标和 Vite 中无效的 `use client` 指令。
- 补齐目录职责、迁移规则与可复现的性能测量脚本，复用现有运行时与锁定依赖。

## 发布验证

本地通过 1,090 项前端测试、8,846 / 8,846 行覆盖、17 项生产浏览器回归、320 项 macOS Rust 测试、严格 Clippy、生产构建与隔离真实启动。SQL 迁移回归使用独立 SQLite，验证旧配置保留、事务失败回滚、恢复重试及已升级数据库的幂等启动。

沿用共享前端、Windows / macOS Rust 质量门禁、真实启动检查、macOS 双架构构建、Tauri 更新签名与六项发布资产 / 更新清单检查。正式安装由用户自行更新。
