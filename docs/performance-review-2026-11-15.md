# 桌面性能检测（2026-11-15）

基线为 v1.1.45（`bffaf06a4924ddef758fee49590ec1923c7b6811`）。本次性能改动纳入 v1.1.46，开发分支为 `codex/desktop-performance-review`；本机正式安装由用户自行更新。

## 检测范围与方法

先读取正式应用与 WebKit 进程的 CPU / RSS，并取线程样本。正式应用播放过程中用户会切歌、切页，因此该数据只作为现场参考；对比使用独立 bundle、隔离数据库和 incognito WebView 的生产构建，避免读写真实账号、曲库或系统凭据。

原生对照均为 About 页面、无歌曲、桌面歌词关闭、音乐伙伴开启、窗口显示；每次采样 20 秒。CPU 使用进程累计 CPU 时间差除以墙上时间，100% 表示一个核心。WebKit 的 GPU 进程数字是该进程的 CPU 使用量，不是 GPU 硬件利用率。

浏览器实验使用已有 Playwright Chromium、生产资源和固定数据。播放场景为 1200 × 800、DPR 2、5000 曲队列与本地有效 WAV，每项采样 5 秒；桌面歌词为独立生产入口、100 行合法逐行 / 逐字歌词。IPC 与外部网络返回模拟数据，浏览器脚本 / 任务耗时不等于整机 CPU。属性观察器、Canvas 计数器对所有对照施加相同测量开销。

## 已落实的优化

| 热点 | 改动 | 行为验证 |
| --- | --- | --- |
| 音乐伙伴每帧重建 SVG | 空闲更新从 60Hz 降为 30Hz；指针、状态、表情和外形过渡保持 60Hz；动画按真实经过时间推进 | 上游形变、注视、主题、冻结 / 恢复、卸载和 120Hz 输入时钟测试通过 |
| 频谱每帧重复映射和绘制 | 保留 220 根柱子，绘制上限 30Hz；频率映射初始化计算一次；平滑、模拟波形与暂停衰减按时间换算 | 真实频率数据、暂停收敛、隐藏 / 恢复、主题、缩放与高刷上限测试通过 |
| 桌面歌词每帧写入 React 状态 | 逐行进度最多 10Hz，逐字最多 30Hz；新 tick、seek 和暂停立即同步 | 120Hz 回调中的状态更新上限和即时 seek / 暂停测试通过 |
| 音乐库根节点无用途的聚合订阅 | 移除 `DesktopLibrary` 的 `useLibrary()` 调用，子页按需要读取切片 | 歌单、收藏、导入与队列回归通过；未单独宣称此项的量化收益 |

歌词与伙伴仍通过 rAF 调度，减少的是状态更新、绘制和样式工作量；不宣称所有回调数量下降。频谱在文档隐藏时另外取消 rAF，可见后恢复。现有媒体会话在固定播放期间没有重复注册或写元数据，未引入另一套媒体会话实现。

## 量化结果

### 固定播放场景

以下为同一测量脚本的基线与最终复测，单位为 5 秒采样中的毫秒。首轮优化对照也观察到相同方向：伙伴开启时，空闲 / 播放脚本分别为 51.3 / 87.1ms；最终为 48.1 / 83.9ms。短样本用于验证收益方向，百分比不外推至所有页面或播放环境。

| 场景 | 脚本：基线 → 最终 | 脚本下降 | 总任务：基线 → 最终 |
| --- | --- | --- | --- |
| 暂停，音乐伙伴开启 | 95.1 → 48.1ms | 49% | 296.2 → 161.6ms |
| 播放，音乐伙伴开启 | 145.5 → 83.9ms | 42% | 416.4 → 247.2ms |
| 全屏播放，音乐伙伴隐藏 | 58.2 → 44.7ms | 23% | 210.0 → 170.6ms |
| 播放，音乐伙伴关闭 | 75.6 → 48.9ms | 35% | 248.3 → 169.6ms |

普通播放的频谱绘制从 300 次降为 150 次 / 5 秒。伙伴空闲场景布局从 301 次降为 154 次。可选 120Hz 定时器模拟中，频谱为 131–133 次 / 5 秒，没有跟随时钟重复同频绘制；该实验不是物理高刷新率屏幕的测试。

### 桌面歌词

| 模式 | 脚本：基线 → 最终 | 脚本下降 | 总任务：基线 → 最终 |
| --- | --- | --- | --- |
| 逐行 | 68.8 → 17.6ms | 74% | 109.0 → 47.1ms |
| 逐字 | 88.9 → 43.4ms | 51% | 289.5 → 180.7ms |

逐字词属性变化由 303 次降为 152 次 / 5 秒，当前词句正确，异常数为 0。此前首轮优化同样观察到逐行 / 逐字脚本下降。

### 原生 WebKit 对照

| 进程 | 基线 CPU | 优化 CPU |
| --- | --- | --- |
| Tauri 主进程 | 3.80% | 2.80% |
| WebKit GPU 进程 | 5.50% | 4.40% |
| 主窗口 WebContent | 5.10% | 3.80% |
| 网络与第二 WebContent | 0.00% | 0.05% |
| 合计 | 14.40% | 11.05% |

该固定空闲场景下降约 23%。RSS 会被系统压缩、共享页面与回收时机影响，未将前后 RSS 变化作为节省内存的证据。最小化实验没有可靠确认后台状态，未用于后台功耗结论；未测电池续航。

### 5000 首长歌单

3 轮预热后执行 30 轮切页、歌单滚动、全屏开关、伙伴菜单与提示框操作，两个对照均约 92.7 秒。

| 指标 | 基线 | 最终 |
| --- | --- | --- |
| 最大渲染歌曲行 | 24 | 24 |
| DOM 节点（全程） | 812 | 812 |
| JS 监听（全程） | 406 | 407 |
| 文档数（全程） | 2 | 2 |
| GC 后堆：首尾 | 9.24 → 10.71MB | 9.24 → 10.73MB |
| 总任务时间 | 8.277s | 7.948s |
| 脚本时间 | 2.638s | 2.552s |
| 页面异常 | 0 | 0 |

新增的一条监听为频谱的 `visibilitychange`，不随切页累积。任务下降约 4%，列表本身已有虚拟化，未再大改。后半段堆趋于稳定；该观察不证明所有时长、网络与平台绝无泄漏。

## 结构与验证

目录职责、遗留内容清理与后续维护点见 [代码与目录约定](./code-structure.md)。保留现有运行时、依赖、锁文件及最新构建产物；本轮隔离测试副本结束后清理，测量 JSON、日志和线程样本保存在本机 Documents 资料目录。

性能改动的验证包括 TypeScript、Oxlint、312 个源文件的架构守卫、47 条 IPC 命令 / 11 个结构的契约检查、127 文件 / 1090 项前端测试、8846 / 8846 行覆盖、17 项浏览器回归、macOS 生产构建和真正启动 / 本地服务健康检查。[性能提交的桌面 CI](https://github.com/alanbulan/TuneFree/actions/runs/43684593754) 通过 Windows 370 项和 macOS 318 项 Rust 测试及两平台构建、启动。

发布整理另外将推荐数据库 SQL 按日期和顺序拆分，保留原版本、事务、参数和延迟重建行为，增加版本记录写入失败的回滚与已升级数据库的重复启动测试。发布版本再次执行共享 Windows / macOS 质量门禁；最终结果见 [v1.1.46 发布记录](./releases/v1.1.46.md)与[正式版本](https://github.com/alanbulan/TuneFree/releases/tag/v1.1.46)。性能数字沿用上述对照，不为 SQL 文件拆分宣称量化性能收益。

## 复现命令

无需增加依赖，使用仓库已有 Chromium 或 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`。

```sh
npm run build
npm run start
```

在另一个终端依次运行，避免性能实验互相干扰：

```sh
PROFILE_OUTPUT=/tmp/tunefree-ui-profile.json node scripts/profile-ui.mjs
PROFILE_OUTPUT=/tmp/tunefree-playback-profile.json node scripts/profile-playback.mjs
PROFILE_OUTPUT=/tmp/tunefree-lyric-profile.json node scripts/profile-desktop-lyrics.mjs
```

播放 / 歌词脚本支持 `PROFILE_DURATION_MS` 与 `PROFILE_BASE_URL`；播放脚本支持 `PROFILE_HIGH_REFRESH=1` 定时器时钟模拟。长歌单脚本支持 `PROFILE_CYCLES`、`PROFILE_HEAP_PREFIX`。测量结束后关闭预览进程。
