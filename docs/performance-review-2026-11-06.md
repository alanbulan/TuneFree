# macOS 歌词交互与性能检查（2026-11-06）

基线为 v1.1.41，本次修复随 v1.1.42 发布。发布按仓库 CI / Release 门禁执行。

## 桌面歌词与其他歌词应用

- 角落 Tooltip 按内容自然宽度显示，受视口宽度限制，并依据实测高度选择上下位置、避开四边。原右下角气泡由 45 × 152px 恢复为 183 × 31.25px。
- 桌面歌词在悬停、拖动、缩放或键盘操作时显示中性灰色圆角边框和底部缩放提示；移开鼠标后隐藏。锁定后隐藏控件、边框与缩放手柄。
- 底层 tao 0.37.2 的 macOS `drag_resize_window` 返回不支持，Tauri 调用不会把这一结果传回前端。原有八方向手柄因此没有真正调整窗口。
- macOS 改用 pointer capture 和物理像素尺寸更新，按窗口缩放比例处理 Retina 坐标；北/西侧保持对边位置，限制最小逻辑尺寸为 400 × 200。只串行提交最新尺寸，避免高频拖动堆积 IPC；快速拖动在初始化完成后仍应用最终位置。其他平台保留原生缩放接口。
- 新窗口默认高度由 300 调至 420，保留用户保存的窗口尺寸。实际 Mac 窗口已验证底边可缩短、拉高，并将最终尺寸保存到配置。
- 默认字号由 22 调至 32px，范围统一为 14–64px。旧版 22px 默认值升级一次，后续主动选择 22px 会保留；其他自定义字号保留。

第三方应用读取音乐信息与 TuneFree 桌面歌词窗口独立。实机验收中，关闭 TuneFree 桌面歌词后，Vorssaint 的 Dynamic Island 仍显示“播放来源：TuneFree”、《阿司匹林》/ 王以太、播放进度，并在歌词按钮开启后显示歌词。现有 Web Media Session 接入可用，因此未增加另一套争夺系统媒体会话的原生实现。

最终依赖下也已复核：持久化开发预览关闭桌面歌词后，Vorssaint 来源列表能选中“TuneFree 开发预览”，显示《给我一个理由忘记》/ 黄丽玲、进度和歌词。读取接口同时取得专辑《寂寞不痛》、285.60 秒时长、播放位置与倍速 1。原先冒烟模式采用非持久化 WebView，此模式下实测系统只返回播放状态和空白标题；对外媒体集成验收应使用持久化配置。开发预览使用独立 bundle identifier，避免占用正式版的应用配置；“关于”页实际显示 macOS arm64。

Vorssaint 根据媒体元数据自行查找歌词；它并非直接读取 TuneFree 的 LRC。可显示哪些歌曲的歌词，仍取决于 Vorssaint 的歌词服务与导入内容，不能据单首歌保证所有歌词应用与所有曲目。

## 已修复的资源和性能问题

| 问题 | 修复与验证 |
| --- | --- |
| 页面切换时中断的 Motion 时间线留在长期存活的 scope | stop 后移除 scope 中的对应播放对象。80 轮对照中，原生 Animation / KeyframeEffect 各增长 320，修复后各增长 0；最终 Framer Motion 14.10.0 的 30 轮复测也各增长 0。 |
| 首页榜单缓存无容量上限 | 改用已有的 BoundedCache，来源最多 8、详情最多 24，TTL 3 分钟；命中不续期，测试验证淘汰和过期重取。 |
| 停用音源后排队请求仍可能启动，且队列无界 | 限制 6 个活跃请求、64 个排队请求；取消同时拒绝待执行队列。1000 请求压力测试为 6 活跃、64 排队、930 拒绝，取消后无新请求启动，完成 1000 个回执且无残留计时器。 |
| 取消推荐后子任务仍持有网络连接 | 搜索与补封面改用 JoinSet，父任务销毁时中止子任务。两个真实 TCP/TLS 等待连接的回归测试验证取消后释放连接。 |
| 替换/销毁音频元素时未立即清理缓冲和节点引用 | 暂停、解绑、移除 src 后调用 load，清空音频与 Web Audio 节点引用，关闭 AudioContext。 |
| 装饰宠物在高刷新率屏幕重复渲染和测量 | 装饰 SVG 更新限制 60Hz，缓存几何边界并在指针、滚动、缩放和 ResizeObserver 变化时失效；卸载释放监听与动画帧。 |

同一 About 页面空闲 5 秒的前后对照（Chromium，1200 × 800）中，Layout 次数从 600 降至 300，脚本时间从 125.3ms 降至 88.5ms，总任务时间从 374.7ms 降至 290.3ms。这些是固定场景数据，不代表所有使用场景同比提升。

5000 首歌单使用虚拟列表，压力场景中最多渲染 24 行。80 轮切页/83 次全屏播放器开关后，DOM 节点、事件监听与文档数量保持 825 / 403 / 3，页面异常数为 0；GC 后 JS 堆从 9.22MB 至 11.02MB，增长主要为 JIT 编译缓存。最终依赖下的 30 轮复测约 92 秒，JS 堆从 9.23MB 至 10.58MB，DOM / 监听 / 文档计数相同，异常数仍为 0。

原生 release 主进程单独测量 122 秒：预热后 RSS 约 119MiB，空闲 CPU 为 0–0.1%；首尾两次 `leaks` 均为 0，末次 footprint 32.4MiB、峰值 34.9MiB。该数据只覆盖主进程，WebKit 子进程另行运行；浏览器压力场景使用 Chromium 和本地固定数据，不能据此证明真实 WebKit 长时播放或所有网络环境绝无泄漏。
