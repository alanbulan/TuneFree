# macOS 窗口恢复与模型请求修复

修复版本：v1.1.43，基线版本：v1.1.42。

## macOS 窗口生命周期

旧版仅通过托盘和单实例插件恢复窗口。macOS 对已运行应用的 Dock / Finder 打开操作会发送 `RunEvent::Reopen`，不会启动第二个实例，因此主窗口隐藏或最小化后没有触发恢复。实机复现中，主窗口不在屏幕，桌面歌词仍显示。

现在无论 `has_visible_windows` 是否为真，都恢复主窗口；桌面歌词可见不能代表主窗口可见。恢复时同时解除 NSApplication 的隐藏状态，再显示、取消最小化并聚焦主窗口。Cmd-Q 和“退出应用”继续彻底退出。

关闭选项文案从“最小化到托盘”调整为“后台运行”，说明再次打开应用或点击托盘可以恢复。已有的关闭偏好值保持兼容。

实机修复预览验收：

- 最小化后再次打开，主窗口从不可见恢复到可见。
- 关闭主窗口选择后台运行，桌面歌词仍可见；再次打开恢复主窗口。
- Cmd-H 隐藏整个应用后再次打开，应用和主窗口恢复可见。
- Cmd-Q 退出后，进程和所有预览窗口均消失。

窗口可见性通过 macOS CGWindowList 与 NSRunningApplication 只读信息核对，UI 动作通过原生界面执行。

## 测试连接成功但生成歌单失败

实际数据库中的失败请求集中在 8000–8002 毫秒。连接测试只生成 `{"ok":true}`，完整选曲或重排的响应耗时更长，旧版默认 8 秒会在读取正文时超时。reqwest 的正文超时可能表现为 `error decoding response body`，之前直接显示该错误，容易误判为返回格式问题。

默认模型超时调整为 60 秒，高级设置最大允许 180 秒。一次性数据库迁移仅把旧版 8 秒默认值升级为 60 秒，保留其他自定义设置；迁移后主动选择的 8 秒也会保留。请求头、正文和整个兼容尝试超时均明确提示“模型服务请求超时”，并说明当前上限和调整位置。错误不再附带模型服务 URL。

在用户当前正式应用中保留服务地址、模型和密钥，仅调整超时后，实测：

| 请求 | 用时 | 结果 |
| --- | --- | --- |
| “下雨天的咖啡馆”场景选曲 | 15199 毫秒 | 12 首歌曲，界面显示完整结果 |
| 云端重排 | 17500 毫秒 | 30 项结果 |
| 发现计划 | 21705 毫秒 | 6 项结果 |

新增真实 TCP 回归：连接探测立即成功，完整正文延迟超过旧版 8 秒后仍可按配置成功返回；正文超时按超时提示且不重复请求。迁移测试覆盖旧默认值升级、保留自定义值和只执行一次。

本次验证不能保证服务商在所有网络条件下均于设定时限内响应；真正超时时会明确提示，可调整等待时间。
